# 健康与健身模块演进计划

> 状态：完整路线已拆分，按批次执行中。本文保存产品判断、实施顺序、验收记录和边界，避免会话上下文变化后丢失约定。
> 最近更新：2026-11-13

## 1. 产品方向

将「健康」定位为被动记录与身体状态观察，将「健身」定位为主动训练、计划和进步。二者保持独立入口与数据边界；未来可以在分析层交叉引用体重、睡眠、营养和训练，但每条结论都要说明数据范围与依据。

- 健康：体重、睡眠、摄入、身体测量等日常记录。
- 健身：训练记录、计划、动作、训练进步等主动行为。
- 训练已经从健康页独立为 `/training`（本仓库当前工作区已完成第一步）。
- 睡眠条的时间轴覆盖记录归属日前一天 00:00 至次日 00:00（48 小时），颜色由睡眠时长、入睡时刻、已记录的夜醒与主观质量综合决定。
- 不自动生成记录，不为缺失字段填造默认值。没有数据就显示「尚无记录」。
- 估算值明确标注「估算」；提示温和、可关闭，避免诊断或强制建议。

## 2. 对现有提案的取舍

第三方分析中涉及的历史统计、个人资料与健康结论，实施前必须从应用当前数据及其日期范围重新核实。BMI 和身高不能单独证明肌肉量；固定建议体重区间、体脂分类、训练失衡结论都不能直接作为应用事实。

- 优先补齐真实可记录的数据，再做派生指标，最后考虑主动提示。
- 围度是身体变化的补充观察数据，和体重分开保存；页面可以并列展示趋势。
- 身体测量可按次选择填写腰围、腹围、胸围、四肢围度、颈围或实测体脂率；不强制一次填全。
- 腰高比属于筛查参考，不是诊断。若后续增加，必须标示计算方式、测量日期与适用限制，不输出「可以放心」等医学结论。
- 体脂率估算、能力基线、照片时间轴、多轨目标、自动提醒、训练热力图、动作级 1RM 与自重有效负荷不进入当前批次。
- 训练容量没有外部重量时，不应把缺失数据伪装成 `0 kg`；训练周目标未设置时，不应显示无配置依据的 `0/3`。
- 饮食快速记录可以作为后续体验改进，但不得自动填时间或营养数值，也不删除细项记录能力。

## 3. 完整实施清单

以下任务覆盖当前获准的健康 / 健身产品方向。每项单独落地与验收；已存在的功能先对照现状，不重复造。工作区其他协作者的未提交改动不属于本计划。

### A. 模块边界（已完成，工作区待整体验收）

训练拥有独立入口，健康首页不再承载训练卡片；旧训练 URL 继续重定向兼容，提醒仍可在应用级触发。

### A0. 睡眠时间轴与综合颜色（已完成）

1. 时间轴中心为 00:00，左侧 -24h、右侧 +24h，覆盖前一日 00:00 到记录归属日后的 00:00；记录归属日按起床日处理。
2. 实际睡眠时段按入睡 / 起床跨午夜定位，显示在理想窗口之上；极端长时段裁切到 48 小时边界，不让图表溢出。
3. 红到绿只表达可视化参考分，不是医疗评分。时长与理想入睡时刻始终参与；夜醒次数 / 分钟与主观质量仅在用户填写时参与，缺项不按负分处理。
4. `healthViz.test.ts` 覆盖跨午夜、归属日定位、长时段、理想窗口和颜色评分因素。

### B. 身体测量（已完成）

目标：用户能按日期记录腰围，并查看历史趋势。腰围记录是独立健康测量数据，不修改健康档案、体重历史或训练模型。

追踪例子：用户在 2026-11-13 输入 `74 cm` → 保存为该日期的一条测量 → 页面显示该点与历史趋势 → 健康分区备份可导出并导入恢复该条数据。

已完成：

1. 可选择日期并记录腰围（cm）；同一天再次保存更新当天记录，避免无意重复。
2. 可只填本次测量的腰围、腹围、胸围、上臂围、大腿围、小腿围、颈围或实测体脂率；身体脂肪不自动估算。
3. 页面可切换不同项目看历史值与趋势；少于两条时如实展示单点，不画伪造曲线。
4. 腰围与身高同时存在时展示腰高比，并标注筛查参考、非诊断。
5. 独立测量实体进入 Dexie 与桌面 SQLite；旧 SQLite 腰围表安全迁移为可选字段；健康分区备份、冲突比较、导入报告与数据概览保留支持。

已完成：测量趋势与体重趋势在同页并列查看，仍保持各自独立存储。

不做：自动估算体脂率或肌肉量；默认推荐固定体重区间；用单次围度推断健康状态。

### C. 摄入记录减负（餐次合并与时间真实性已完成）

1. 一次添加的多种食物保存为一个餐次记录，营养成分逐项快照保留；单项原有食物关联仍保留。
2. 保留现有单项 / 套餐 / 一句话录入；常用餐可复用，不强迫拆分。
3. 时间与金额不静默填默认值；用户没输入时按未记录处理。
4. 验收：一餐选中多项后保存一条摄入，分项营养、统计汇总、编辑、删除、导出导入均不丢；缺时间时仍可保存。

### D. 训练统计可信化（第一批已完成）

1. 未填写负重时显示「未记录负重 / 尚无容量数据」，不能显示 `0 kg`。
2. 用户未启用训练计划时不显示伪造的 `0/3`；启用后才按其目标显示进度。
3. 自重动作容量暂不换算；若未来实现，需记录当天体重快照、明确动作系数来源并标「估算」。
4. 周统计根据有效负重组数区分容量数据与资料不足；周目标未配置时仅展示训练次数。

已完成：餐次组合已提取为纯计算函数并有测试；新建摄入、收支、睡眠、训练不预填时刻；导入中缺失或非法的记录时刻保留为空。训练页无负重组时不显示 `0 kg`，未启用训练计划时不显示 `0/3`。旧记录中已经保存的时刻原样保留。

### E. 训练进步回顾（首版已完成）

1. 按动作名显示近 30 天最近 8 次的最高次数、最高负重与趋势；不同动作分开比较，不把容量拼成“肌肉量”。
2. 最近 3 次可比较记录完全相同时显示可收起的温和提示；负重或次数不同会重置判断。
3. 周回顾显示训练天数与部位记录覆盖；未分类项目单列，不判定“失衡”。
4. 可复制最近整场；可把已保存记录另存为命名模板并用于新训练。模板保存在训练计划档案中，随健康分区跨端保存和备份；起新记录时清空日期相关时刻、感受与备注。
5. 保存后按同名动作对比近 30 天历史的最高次数 / 负重；缺少对应实测数据时不显示该项，不把缺失填成 0。
6. AI 点评由用户主动触发，只把所选周的训练记录发送给已配置模型；不自动调用，不读健康或收支数据，结果标记为 AI 生成且不存为训练事实。

### F. 多轨目标（已完成首版）

1. 支持用户自行设置体重区间、腰围目标、力量基线 / 目标与行为目标；任何目标都不预填推荐值。
2. 目标可以单独启用、编辑、暂停、删除；按周 / 月展示达成记录，不因漏记判失败。
3. 训练频次目标复用训练计划目标，避免两处冲突配置。

### G. 派生指标（首批已完成；主动提示另行评审）

1. 仅基于已有记录计算近 30 天平均蛋白质克数 / kg、训练记录日与未记训练日的摄入、入睡时刻偏移、记录覆盖天数；显示区间与样本量。
2. 蛋白目标已支持用户在目标页自行设置；当前指标页不套用固定摄入建议，也不把估算体脂或 TDEE 包装成实测。
3. 暂不主动推送建议。今后若加提示，再单独评审触发数据量、关闭方式与提醒频率；不得对缺记录的天数作负面推断。
4. 不自动补记录，不将缺失当成零，不展示无数据图表。

### H. 记录可复用与回顾导出（现有能力审查完成）

1. 常用餐从食物库 / 套餐选择并可逐项调整；训练支持复制最近整场与命名模板，均保留编辑核对。
2. 全库分区 JSON 备份可往返恢复；挑选记录 JSON 导出支持选定记录；训练 / 睡眠另有单条 JSON 导出。当前不重复增加 CSV 周报出口。PDF 周报和进度照片时间轴另列独立设计评审。
3. 所有新用户数据或设置必须满足备份 / 恢复硬规矩与跨端一致性。

## 4. 实施与验收约定

- 每个批次先盘点调用链和数据契约，再做最小改动；不覆盖工作区中其他协作者的未提交修改。
- 健康新记录必须同时完成本地存储、桌面存储、备份读写、数据页可见性与往返测试。
- 用户可见文案走 `src/shared/i18n` 的九份消息表，新增占位符保持一致。
- 完整路线顺序：A → B → C → D → E → F → G → H。模块内可在不改变产品边界的前提下微调依赖顺序。
- 每阶段验收必须覆盖可见行为、数据持久化、备份往返、旧数据兼容和无数据状态；训练模块按自己的指导文档同步销账。
- 批次完成后运行仓库约定的 `npm test`、`npm run typecheck`、`npm run lint`，并报告结果和仍未解决的限制。

### 本批次可追踪链路

- 睡眠颜色：`HealthPage / SleepsPage → SleepBar → healthViz.sleepBarScore / sleepBarColor`；核心输入是用户设定的理想作息与本夜实际时长，夜醒和主观质量是可选输入；`healthViz.test.ts` 固定跨午夜与评分例子。
- 身体测量：`MeasurementsPage → healthRepo → DiaryStore → Dexie / SQLite → health backup`；日期是记录主键，同日保存更新，字段各自可空。
- 训练模板：`TrainingDetailDialog → TrainingPage.handleSaveTemplate → HealthProfile.trainingPlan.templates → Dexie / SQLite → health section backup`；例：详情保存「推日」后，点模板入口启动一条新记录，日期用当前查看日、时刻 / 感受 / 训练备注留空，动作与组可继续编辑。
- 训练即时对比：`TrainingForm.save → TrainingPage.handleTrainingSaved → compareTrainingWithHistory`；仅比较同名动作近 30 天历史的最高次数与明确负重，只在有前次记录且指标不同时时以 toast 提示。
