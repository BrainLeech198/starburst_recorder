# 管理员工作台体验优化清单

> 目标：在现有静态管理页与 Worker API 契约上，逐项提升发布安全、公告查找、编辑保护和操作反馈；保留现有视觉风格，不引入 UI 框架，也不改变邮件/公告的服务端投递语义。
> 建立时间：2026-11-04。每项完成后记录验证与提交，避免清单只停留在计划。

## 现状基线

- 管理页面：`site/admin/` 的原生 HTML、CSS、JavaScript。
- 管理 API：`worker/push/src/index.js`；公告列表、原位编辑、删除接口已上线。
- 会话只保存在页面内存，30 分钟后 API 返回 401 时回到登录页。
- 发布普通应用内公告会直接提交；发送邮件或发布紧急公告会调用浏览器原生 `confirm()`。
- 公告历史当前一次加载全部记录，支持编辑与删除，但没有搜索或级别筛选。
- 编辑过程点“取消编辑”会直接清空表单；服务端保存失败时会保留输入。

## 设计参考与采用原则

- [Carbon Design System：Data table guidelines](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)：数据列表的搜索、筛选和行内操作应在列表附近；列表很小时保留少量直观行内操作，不为形式引入复杂表格。
- [Microsoft Fluent 2：Dialog usage](https://fluent2.microsoft.design/components/web/react/core/dialog/usage)：只在可能造成损失或需要明确决策时打断用户；标题要说明决定内容，关闭后焦点回到触发控件。
- [GOV.UK Design System：Recover from validation errors](https://design-system.service.gov.uk/patterns/validation/)：失败后保留用户已输入内容，并清楚说明问题与修复方式。
- 落地时优先复用项目现有暗色主题、CSS 变量、原生平台能力和 Worker API；不复制参考站点代码，不增加依赖。
