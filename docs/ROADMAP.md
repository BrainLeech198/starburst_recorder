## 许可红线（抄作业前先看）

- **AGPL-3.0**（思源、logseq、Trilium、khoj、reor、cherry-studio、immich、wger、Open Food Facts）：**只能借鉴思路 / 架构 / 数据模型，不要抄代码**——AGPL 一旦使用，我们这份也得跟着以 AGPL 开源（**联网提供服务也算**）
- **GPL-3.0**（openScale）：同上
- **MIT**（memos、one-api、silverbullet）：**可以抄代码**，保留声明即可
- **自定义 / 无许可**（joplin、open-webui、waistline 完全没有许可文件）：只读文档、借鉴思路，**代码一律不抄**

> 一句话：**架构与数据模型大胆借鉴；代码只从 MIT 项目里拿。**

## 0. 先验证核心假设（最便宜、决定方向）⭐

用 3–7 天真实记录，让 AI 出一次「这周发生了什么」，然后问自己：**还想不想看下期**。

- 为什么：产品卖点就是"随手记 → AI 整理出报告"，但现在 AI 只有"单日整理成日记"这一档，**跨天/跨周聚合从没试过**——卖点成不成立，这一步就能问出来
- 参考：`khoj`（`documentation/docs/features/chat.md`）
- 产出：一个决定——AI 当主角继续做深，还是降级为辅助

## 1. 把"记录"主线做深（天天摸的部分）

1. **AI 周报 / 月报**（把第 0 项落地成产品功能）
2. **标签 + 搜索 + 时间轴过滤**（随记现在只能按天翻）— 参考 `memos`（MIT，标签）、`immich`（`features/searching.md`）
3. ✅ **天气查询**（2026-10-21：Open-Meteo 免费无 Key；天气弹窗里点「查天气」→ 自动定位或搜城市 → 结果由用户决定「填上 / 不用」，不自动写库）
4. **结构化录入**：从一句话里认出时间/天气/金额 — 参考 `silverbullet` 的 Space Lua 查询（MIT）
5. ✅ **图片导入 / OCR**（2026-10-21：手写照片 → 视觉模型转文字 → 新建当天日记进编辑页；图片不落库）
6. **数据可视化**：体重、心情、消费趋势（给健康/经济模块铺路）

## 2. 手机端收尾（"能不能日常用"的门槛）

7. ✅ 状态栏/刘海安全区、✅ 验证「导出全部数据」在 WebView 里可用（2026-10-21：导出改用系统 SAF 保存对话框，端到端验过）｜✅ 实体返回键接路由（2026-10-21：弹窗 → 上一级 → 首页再按一次退出，真机已验）
8. 装 APK 真机用一周（替掉纸笔，才是真验收）

## 3. 数据安全（越晚做越贵）

9. **自动备份**（定时导出到指定目录；桌面端好做，手机端受限）
10. 备份格式升级（现在是单个 JSON）— 参考 `memos` 的 `docs/design/memos-export-format.md`（MIT）
11. **SQLite 收尾**：✅ 桌面端 2026-10-21 已换（`node:sqlite` + 手动搬旧数据）；剩 **Android**（`@capacitor-community/sqlite` + 真机验证）— 见 PROJECT-NOTES §10

## 4. 家庭系统（方向已定，顺序：APK → 健康模块 → 账户）

12. **健康模块骨架**（✅ 饮食、✅ 睡眠最小闭环、✅ 每周空腹称重与推算 TDEE（2026-10-29）；训练还没有）— 数据模型抄 `wger`，食物库直接用 Open Food Facts API
13. **账户与共享**（PocketBase + 默认全不共享 + 双向开放）— 权限交互抄 `immich` 的 Partner Sharing

## 5. 工程与对外（低成本高回报）

### 7.3 如果只做三件

1. **把助手记忆与会话纳入备份**（M）——补上"卖点资产不能迁移"这个最扎眼的漏洞。
2. **目录化 Markdown 导出（图片落盘）+ 收支 / 训练 CSV**（M）——外部证据最密集，顺带解决 7.1-B 缺的三类导出。
3. **健康趋势图 + 回顾算热量**（M）——数据已经攒下了，缺的是让用户看见它在起作用，比再加一个新模块更能留人。

代价分别是：1 要定备份格式的版本升级与合并语义；2 会让备份从"单个 JSON"变成多文件结构，这份简单性当初是有意选的；
3 要先统一口径（称重史 120 条裁剪、回顾不算热量都在这条链上）。

### 7.4 需要用户拍板 / 明确不做

- **全局快捷键**：外部调研建议加，但 [PROJECT-NOTES.md](PROJECT-NOTES.md) §5「桌面托盘常驻」记着当初明确要求"**不要全局快捷键，不能影响其它软件**"。要翻案由用户定，AI 不自行推翻。
- **训练的动作库自定义 / 负荷趋势**：TRAINING-MODULE 里是刻意划出的边界（不做），翻不翻案先定方向再动手。
- **双向家庭共享（账号 + 服务器）**：顺序仍是 APK → 健康 → 账户，当前不做（§4 已定）。
- **首页简化（长辈关怀的信息密度收缩）**：仍是 TODO，等明确"简化到什么程度"再动。
